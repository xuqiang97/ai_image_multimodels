## 1. 本期目标

本期将 AI 生图从单 LinkFox 模型升级为三模型并行：用户可在同一任务中按“模型 × 图片类型”配置计划张数，由各模型并行产出图片。

| 范围 | 本期要求 |
| ---- | -------- |
| 模型 | LinkFox、自研、阿里绘蛙 |
| 美工版 | 系统 SKU 维度，支持场景图 / 白底特写 / 特写图 / 卖点图 |
| 运营版 | 店铺 ASIN 维度，支持上述 4 类 + 标准普通 A+ 图 |
| 页面 | L1 任务列表、L2 审核工作台、L3 沉浸式大屏 |
| 操作 | 新增、编辑、查看、批量导入、批量修改、提交、复制、批量复制、重跑 |
| 兼容 | phase 1 单 LinkFox 老任务继续可查看、编辑、复制、重跑、筛选 |

## 2. 核心规则

### 2.1 模型与图片类型

| 模型 | 缩写 | UI 颜色 | 本期说明 |
| ---- | ---- | ------- | -------- |
| LinkFox | LF | 蓝 | 默认启用；支持标准普通 A+ 图 |
| 自研 | 自研 | 绿 | 新增接入；标准普通 A+ 图上限默认为 0 |
| 阿里绘蛙 | 绘蛙 | 橙 | 新增接入；运营版默认不配置额度或上限保持 0 |

### 2.2 多模型矩阵

- 横轴为模型，纵轴为图片类型，cell 表示某模型在某图片类型上的计划张数。
- 上线后固定展示 LinkFox、自研、阿里绘蛙 3 个模型；未配置额度按上限 0 处理。
- 固定展示不等于默认启用；D1 / M1 默认仅启用 LinkFox，用户启用其他模型后按后台上限自动填入默认值。
- 输入范围为 `0` 到后台上限；未配置额度时显示 `≤0` 且不可输入。
- 标准普通 A+ 图当前仅 LinkFox 可输入；自研 / 绘蛙通过后台上限为 0 控制。
- 启用模型但所有 cell 均为 0 属于“软关闭”：编辑态保留，列表态隐藏。

### 2.3 额度与状态

| 场景 | 规则 |
| ---- | ---- |
| 提交任务 | M3 按模型和图片类型校验额度；任一不足则整体阻断 |
| 生成失败 / 任务取消 | 已占用额度按失败或取消部分“返还”或“释放” |
| 后台额度下调 | 历史任务值不自动截断；D2 编辑时超过当前上限的 cell 标红并阻断保存 / 提交 |
| 部分模型失败 | 不影响其他模型、其他图片类型继续生成 |
| 任务级状态 | 由各模型 / 图片类型子任务聚合得到 |
| 文案 | 报错使用模型全名；额度文案使用“返还 / 释放”，不用“免费” |

### 2.4 展示口径

| 口径 | 规则 |
| ---- | ---- |
| `—` | 没有图片可审，例如某模型生成全失败 |
| `0` | 有图片进入审核，但审核通过数为 0 |
| 配置信息列 | 展示模型 pill、总计划、图片类型 breakdown；类型层不隐藏 0，模型层隐藏全 0 |
| 进度 / 结果列 | 展示整体汇总，同时展示 per-model 明细 |
| 模型筛选 | 5 个 Tab 统一支持模型多选；多选为 OR；空选为全部；筛 LinkFox 需命中老任务 |

示例：

| 模型 | 计划 | 生成成功 | 审核通过 | 审核位 |
| ---- | ---: | -------: | -------: | ------ |
| LinkFox | 14 | 12 | 8 | `8` |
| 自研 | 8 | 0 | - | `—` |
| 阿里绘蛙 | 10 | 8 | 0 | `0` |

### 2.5 复制与重跑

复制、批量复制、重跑都等价于“基于原任务创建新任务”，不改写旧任务，也不引入版本号。

新任务必须完整继承：

- 启用模型集合。
- 多模型矩阵全部数值。
- LinkFox 专属字段：生成图片语言、卖点图排版版式、A+ 图排版版式、该图对应卖点等。

phase 1 老任务保持单 LinkFox，不自动补齐自研或绘蛙。

## 3. 页面要求

页面细节以 `index.html` 的 S1-S17 为准，PRD 只列核心产品规则。

| 范围 | 规则 |
| ---- | ---- |
| S1-S5 额度与任务配置 | 顶部额度、D1 / D2 / D3、多模型矩阵、LinkFox 专属字段 |
| S6-S9 批量与提交 | M1 / M2 / M3、复制 / 批量复制 / 重跑完整继承配置 |
| S10-S14 列表层 | 模型筛选、配置列、进度列、结果列、全链路列均支持多模型 |
| S15-S17 审核与大屏 | L2 分组头 / 卡片展示模型来源；L3 顶部模型 Tag 随当前图片刷新 |

补充规则：

- M1 批量导入支持美工版 SKU / 运营版 ASIN；默认策略与 D1 一致，默认仅启用 LinkFox；导入阶段只做基础校验，不做每日额度校验。
- M2 批量修改 cell 三态：留空 = 不修改，`0` = 改为 0，`>=1` = 改为指定张数。
- D3 查看只读展示，仅渲染任务实际启用的模型列。
- 生成图片语言字段仅影响 LinkFox；自研 / 绘蛙本期按英语生成，不受该字段影响。
- L3 右栏保留原 LinkFox 相关字段，并将原“LinkFox任务id和图片id”泛化为“第三方 id”：三模型均按 `任务id_图片id` 展示，自研需在上线前补齐图片 id。

## 4. 研发与上线关注

### 4.1 接入与数据

| 事项 | PRD 关注点 |
| ---- | ---------- |
| 模型接入 | 三模型均按“创建生成任务 + 查询生成结果”的异步链路理解 |
| 业务层口径 | 任务创建、额度校验、状态汇总、列表展示尽量保持统一规则 |
| 子任务明细 | 建议研发优先评估 `subtask` 子任务表或等价明细结构，表达“模型 × 图片类型”粒度 |
| 数据覆盖 | 研发方案需覆盖子任务、图片结果、模型额度配置、审核聚合、部门 / 团队 / 用户统计和 BI 同步，避免只处理主任务字段 |

### 4.2 授权与费用风险

| 风险 | 处理建议 |
| ---- | -------- |
| 自研授权可能改为 OAuth2 | 研发方案前确认；未明确要求 OAuth2 前，按现有 Basic Auth / Bearer Token 推进 |
| 阿里绘蛙全司共用 appkey | 美工版可优先开放；运营版默认不配置额度或上限保持 0，待分账 / 欠费影响机制确认后再启用 |

## 5. 验收重点

| 模块 | 重点 |
| ---- | ---- |
| 新建 / 编辑 / 查看 | 默认 LinkFox、启用模型默认值、红警态、只读展示、LinkFox 专属字段 |
| 批量导入 / 修改 / 提交 | M1 基础校验、M2 三态、M3 额度不足阻断 |
| 列表 / 审核 / 大屏 | 模型来源、per-model 进度和结果、`—` 与 `0`、L2 / L3 来源展示 |
| 复制 / 重跑 | 启用模型、矩阵数值、LinkFox 专属字段完整继承；旧任务不被改写 |
| 老任务兼容 | phase 1 单 LinkFox 老任务可查看、编辑、复制、重跑，筛 LinkFox 可命中 |
| 数据与 BI | 如业务库有新增字段 / 表，验收前确认 BI 库和 T+1 同步已更新 |

验收数据需覆盖：三模型额度配置、美工版 / 运营版、phase 1 单 LinkFox 老任务、未配置额度场景（验证 `≤0`）。
